# tyme4ts monorepo 仓库管理与集成说明

> 本文档面向维护者、扩展包开发者与集成方，说明 tyme4ts fork 仓库（`tw-master` 分支）的 monorepo 结构、官方同步流程、扩展包开发指南及集成规范。

---

## 一、仓库结构概览

```
tyme4ts/
├── lib/                           # 官方库源码（零侵入，仅读）
├── test/                          # 官方库测试（mocha）
├── packages/
│   └── almanac/                   # 太微公共通书扩展包
│       ├── src/                   # 扩展包源码
│       ├── test/                  # 扩展包测试（vitest）
│       ├── rules/                 # 版本化规则资产
│       ├── package.json           # 依赖 workspace:* 源码联动
│       └── README.md
├── package.json                   # 根包配置（含 workspaces + 聚合脚本）
├── pnpm-workspace.yaml            # pnpm workspace 定义
├── pnpm-lock.yaml                 # pnpm 锁文件（monorepo 统一）
├── .gitignore                     # 忽略 dist/ 与 node_modules/
└── docs/                          # 本文档及项目文档
```

**关键原则**：
- **官方库零侵入**：扩展包（`@taiwei/tyme4ts-almanac`）通过 `Adapter` 只读官方公开 API，禁止修改 `lib/`、`test/` 或任何官方源码
- **源码联动**：扩展包依赖 `"tyme4ts": "workspace:*"`，指向根包，改官方库立即触发类型检查
- **双测试隔离**：官方库测试（`mocha`）与扩展包测试（`vitest`）独立运行，互不污染

## 二、开发环境准备

### 2.1 安装依赖

在仓库根目录执行：

```bash
# 删除旧 npm 锁文件（如有）
rm -f package-lock.json

# 安装 pnpm（如未安装）
npm install -g pnpm

# 安装 monorepo 依赖
pnpm install
```

**关键产物**：
- `pnpm-lock.yaml`：monorepo 统一锁文件（删除 `package-lock.json` 避免冲突）
- `node_modules/`：pnpm 硬链接结构（严格隔离，无幽灵依赖）

### 2.2 构建官方库（扩展包开发前置条件）

扩展包依赖 `workspace:*` 解析到根包，类型检查需官方库的构建产物（`dist/lib/index.d.ts`）。**首次开发或改官方库后需构建**：

```bash
# 构建官方库（生成 dist/lib/）
pnpm build

# 验证构建产物
ls dist/lib/index.d.ts
```

**说明**：
- `dist/` 被 `.gitignore` 忽略（上游 6tail 约定），不入库
- 构建产物是临时中间产物，提交前无需保留（CI 流程中重建）

## 三、扩展包开发指南

### 3.1 扩展包开发流程

1. **进入扩展包目录**（可选，根目录也可通过 `pnpm --filter` 调用）：
   ```bash
   cd packages/almanac
   ```

2. **修改源码或规则资产**：
   - 源码位置：`src/adapter-tyme4ts.ts`、`src/providers.ts` 等
   - 规则资产：`rules/packages/`（规则包）、`rules/sources/`（来源包）、`rules/golden/`（黄金案例）

3. **类型检查**：
   ```bash
   # 在扩展包目录
   pnpm check

   # 或在根目录
   pnpm check:almanac
   ```

4. **运行测试**：
   ```bash
   # 在扩展包目录
   pnpm test

   # 或在根目录
   pnpm test:almanac
   ```

5. **构建扩展包**：
   ```bash
   pnpm build
   # 生成 packages/almanac/dist/
   ```

### 3.2 开发前置条件（重复强调）

**扩展包开发前必须先构建官方库**，否则类型检查失败（找不到 `tyme4ts` 的 `.d.ts`）：

```bash
pnpm build && pnpm check:almanac
```

### 3.3 扩展包的依赖管理

- **官方库依赖**：`"tyme4ts": "workspace:*"`（固定，勿改）
- **其他依赖**：直接在 `packages/almanac/package.json` 添加，根目录 `pnpm install` 会自动安装

### 3.4 规则资产更新

规则资产位于 `packages/almanac/rules/`，需版本化管理：

```
rules/
├── packages/2026.07.25.json          # 规则包（版本号即文件名）
├── sources/2026.07.25.json           # 来源包
├── golden/tyme4ts-1.5.2.json         # 黄金案例（按上游版本）
├── allowed-differences.json           # 允许差异清单
├── release-manifest.json             # 发布清单
└── review-checklist.md               # 审核清单
```

**更新规则时**：
1. 新建 `rules/packages/<新版本>.json`
2. 更新 `release-manifest.json` 指向新版本
3. 更新 `rules/review-checklist.md` 记录变更
4. 运行 `pnpm test:almanac` 验证 Schema 校验通过

## 四、官方上游同步流程

### 4.1 同步上游变更

上游仓库：`https://github.com/6tail/tyme4ts.git`（master 分支）

**步骤**：

1. **拉取上游变更**：
   ```bash
   git fetch upstream master
   ```

2. **查看上游变更**：
   ```bash
   git log HEAD..upstream/master --oneline
   ```

3. **评估影响范围**：
   - 若仅改文档/测试 → 可直接合并
   - 若改公开 API → 需更新 `adapter-tyme4ts.ts` 并重跑黄金案例
   - 若改内部实现 → 通常无需动扩展包（Adapter 只读公开 API）

4. **合并上游变更**：
   ```bash
   git merge upstream/master --no-ff
   ```

5. **解决冲突**（如有）：
   - `lib/` 冲突：优先保留上游，仅检查是否有扩展包用到的公开 API 被删除
   - `packages/almanac/` 冲突：保留本地扩展包（上游无此目录）

6. **构建并验证**：
   ```bash
   # 重建官方库（dist/ 清空）
   pnpm build

   # 官方库测试
   pnpm test:official

   # 扩展包测试
   pnpm test:almanac
   ```

7. **更新黄金案例与允许差异**：
   - 若上游有 API 变化导致黄金案例失败，运行 `pnpm test -- golden.test.ts` 查看差异
   - 新增差异加入 `rules/allowed-differences.json` 的 `allowedPaths` 数组（需审核）

8. **提交同步记录**：
   ```bash
   git commit -m "sync(upstream): 同步 6tail/tyme4ts master 分支至 YYYY-MM-DD

   - 合并上游 <commit-count> 个提交
   - 更新黄金案例 <变更数量> 条
   - 允许差异清单新增 <差异数量> 条
   - 扩展包适配调整：<简要说明>
   "
   ```

### 4.2 同步后扩展包验证清单

- [ ] `pnpm build` 成功（官方库构建产物生成）
- [ ] `pnpm test:official` 通过（官方库 363 测试）
- [ ] `pnpm test:almanac` 通过（扩展包 38 测试）
- [ ] `pnpm check:almanac` 通过（扩展包 0 类型错误）
- [ ] 黄金案例对拍无未允许差异（`test/compatibility/golden.test.ts`）
- [ ] 更新 `rules/golden/tyme4ts-<新版本>.json`（若上游有大版本升级）

## 五、测试与验证

### 5.1 测试隔离架构

| 测试套件 | 框架 | 入口命令 | 覆盖范围 |
|---------|------|---------|---------|
| 官方库测试 | mocha | `pnpm test:official` | `test/` 下所有 `.test.ts`（历法算法） |
| 扩展包测试 | vitest | `pnpm test:almanac` | `packages/almanac/test/` 下所有 `.test.ts`（Adapter + Providers + Rules） |
| 聚合测试 | 无 | `pnpm test` | 顺序运行上述两套（根 package.json 定义） |

**关键特性**：
- 扩展包测试**不引用**官方库源码，仅通过 Adapter 测试公开 API 契约
- 官方库测试**独立运行**，不受扩展包污染

### 5.2 黄金案例对拍

黄金案例位于 `rules/golden/tyme4ts-1.5.2.json`，验证 Adapter 结果与上游官方库一致：

```bash
# 运行黄金案例测试
pnpm test -- test/compatibility/golden.test.ts
```

**对拍失败处理**：
1. 查看 `compareAdapterResult` 输出的差异列表
2. 判断是否为预期差异（如上游 API 变更）
3. 预期差异加入 `rules/allowed-differences.json` 的 `allowedPaths`
4. 非预期差异需调查 Adapter 实现或上游回退

### 5.3 规则包 Schema 校验

规则包必须通过 Schema 校验才能加载：

```typescript
import { validateRulePackage, loadRulePackage } from './rules/registry.js'

const rulePackage = JSON.parse(fs.readFileSync('rules/packages/2026.07.25.json', 'utf8'))
const validation = validateRulePackage(rulePackage)
if (!validation.ok) {
  throw new TypeError(validation.errors.join('; '))
}
const loaded = loadRulePackage(rulePackage) // 深度冻结
```

**校验规则**（`src/rules/schema.ts`）：
- `priority` 必须为正整数（越小优先级越高）
- `conclusion` 必须为有效枚举值（8 种结论）
- `confidence` 必须在 `[0, 1]` 范围内
- `reviewStatus` 为 `approved` 时 `confidence` 必须 ≥ 0.8
- `sourceId` 必须以 `model-knowledge.` 前缀开头

## 七、Rust/WASM 集成契约

### 7.1 almanac-contract crate 定位

`almanac-contract` 是 Rust/WASM 侧的**最小引用契约**，位于 `tw-wetp-wasm-core-base/wasm-core/crates/almanac-contract/`。

**设计原则**：
- 仅为专业系统引用通书快照提供稳定字段（`AlmanacSnapshotRef`）
- 不复制 TS 侧完整 DTO（TS 是主实现，Rust 仅为跨端传输）
- 若 WASM 接入同一规则包，再对齐完整 DTO（当前未接入）

### 7.2 Rust 契约字段对照

| Rust 字段 | TypeScript 对应 | 序列化规则 |
|----------|----------------|-----------|
| `ActivityConclusion` | `ActivityConclusion` | kebab-case（`recommend`） |
| `AlmanacHour.branch` | `AlmanacHour.branch` | 原样 |
| `AlmanacHour.civilRange` | `AlmanacHour.civilRange` | 原样 |
| `AlmanacHour.cycle` | `AlmanacHour.cycle` | 原样 |
| `AlmanacHour.conclusions` | `AlmanacHour.activities`（映射为结论列表） | 原样 |
| `AlmanacSnapshotRef.*` | `AlmanacSnapshot.*`（部分字段） | camelCase |

**注意**：`AlmanacHour.conclusions`（Rust）与 `activities`（TS）字段名不同，这是**设计差异**（Rust 侧重结论集合，TS 侧重活动记录），待 WASM 接入时对齐。

### 7.3 Rust 测试运行

```bash
# 在 tw-wetp-wasm-core-base/wasm-core/ 目录
cargo test -p almanac-contract --test almanac_contract
```

**预期结果**：3 测试通过（枚举一致性 + camelCase 序列化 + 版本字段往返）。

## 八、常见问题排查

### 8.1 类型检查失败：`Cannot find module 'tyme4ts'`

**原因**：官方库未构建，`dist/lib/index.d.ts` 不存在。

**解决**：
```bash
pnpm build && pnpm check:almanac
```

### 8.2 黄金案例测试失败：差异未被允许

**原因**：上游 API 变更导致 Adapter 结果差异，未加入允许差异清单。

**解决**：
1. 查看失败输出中的差异字段路径（如 `facts.fetus`）
2. 编辑 `rules/allowed-differences.json`，将路径加入 `allowedPaths` 数组
3. 重跑测试验证

### 8.3 pnpm install 报错：`peer dependency mismatch`

**原因**：根包与扩展包的 `@types/node` 版本不一致。

**解决**：
```bash
# 统一版本到根 package.json 的版本
pnpm install -D @types/node@22.10.10 -w
```

### 8.4 工作区变更丢失：`dist/` 未被 git 跟踪但 CI 失败

**原因**：`dist/` 被 `.gitignore` 忽略，CI 流程需重建官方库。

**解决**：CI 流程中添加构建步骤：
```yaml
- pnpm build
- pnpm test:official
- pnpm test:almanac
```
